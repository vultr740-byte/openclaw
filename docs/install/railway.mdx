---
title: Deploy on Railway
---

Deploy OpenClaw on Railway with a one-click template and finish setup in your browser.
This is the easiest “no terminal on the server” path: Railway runs the Gateway for you,
and you configure everything via the `/setup` web wizard.

## Quick checklist (new users)

1. Click **Deploy on Railway** (below).
2. Add a **Volume** mounted at `/data`.
3. Set the required **Variables** (at least `SETUP_PASSWORD`).
4. Enable **HTTP Proxy** on port `8080`.
5. Open `https://<your-railway-domain>/setup` and finish the wizard.

## One-click deploy

<a href="https://railway.com/deploy/clawdbot-railway-template" target="_blank" rel="noreferrer">
  Deploy on Railway
</a>

After deploy, find your public URL in **Railway → your service → Settings → Domains**.

Railway will either:

- give you a generated domain (often `https://<something>.up.railway.app`), or
- use your custom domain if you attached one.

Then open:

- `https://<your-railway-domain>/setup` — setup wizard (password protected)
- `https://<your-railway-domain>/webchat/` — WebChat UI (same domain as the gateway)

## What you get

- Hosted OpenClaw Gateway + WebChat UI (`/webchat/`)
- Web setup wizard at `/setup` (no terminal commands)
- Persistent storage via Railway Volume (`/data`) so config/credentials/workspace survive redeploys
- Backup export at `/setup/export` to migrate off Railway later

## Required Railway settings

### Public Networking

Enable **HTTP Proxy** for the service.

- Port: `8080`

### Volume (required)

Attach a volume mounted at:

- `/data`

### Variables

Set these variables on the service:

- `SETUP_PASSWORD` (required)
- `PORT=8080` (required — must match the port in Public Networking)
- `OPENCLAW_HOME=/data` (recommended; minimal persistent root)
- `OPENCLAW_STATE_DIR=/data/.openclaw` (optional explicit override)
- `OPENCLAW_WORKSPACE_DIR=/data/workspace` (optional explicit override)
- `OPENCLAW_GATEWAY_TOKEN` (recommended; treat as an admin secret)

If you only set `OPENCLAW_HOME=/data`, startup will derive:

- state at `/data/.openclaw`
- workspace at `/data/.openclaw/workspace`

If you use a different Railway Volume mount path, keep `OPENCLAW_HOME` aligned
to that mount. Only set `OPENCLAW_STATE_DIR` and `OPENCLAW_WORKSPACE_DIR` when
you want explicit non-default paths, and keep them aligned to the same root.

## Env only setup (skip /setup)

If you want a fully automated deploy with no in-browser setup, use the config
template + env variables path.

For path variables, the minimal setup is:

- `OPENCLAW_HOME=/data`

With only that variable set, the entrypoint will derive:

- `OPENCLAW_STATE_DIR=/data/.openclaw`
- `OPENCLAW_WORKSPACE_DIR=/data/.openclaw/workspace`
- config path `/data/.openclaw/openclaw.json`

Set `OPENCLAW_STATE_DIR` or `OPENCLAW_WORKSPACE_DIR` only when you want an
explicit override, such as the legacy/custom workspace layout
`OPENCLAW_WORKSPACE_DIR=/data/workspace`.

Add these variables:

- `OPENCLAW_CONFIG_TEMPLATE=/app/config/openclaw.railway.template.json`
- `OPENCLAW_CONFIG_TEMPLATE_FORCE=1` (optional; overwrite existing config)
- `OPENCLAW_GATEWAY_BIND=lan`
- `OPENAI_API_KEY`
- `OPENAI_BASE_URL`
- `OPENAI_API_MODE=openai-responses` (or `openai-completions` if your proxy requires it)
- `OPENAI_MODEL` (example: `gpt-5.2`)
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_ALLOW_FROM` (comma-separated Telegram user ids, or set `TELEGRAM_ALLOW_FROM_JSON` to a JSON array)
- `OPENCLAW_CONTROL_UI_ALLOWED_ORIGINS` (optional; comma-separated origin list for WebChat/Control UI; if omitted, startup will derive `https://${RAILWAY_STATIC_URL}` when available)

Notes:

- The template sets Telegram to `dmPolicy: "allowlist"`, so no pairing codes are used.
- WebChat is mounted at `https://<your-railway-domain>/webchat/` on the same domain as the gateway.
- By default the template allowlists `https://${RAILWAY_STATIC_URL}` for browser-origin checks; startup also auto-derives this origin when `OPENCLAW_CONTROL_UI_ALLOWED_ORIGINS` is unset.
- If `TELEGRAM_ALLOW_FROM` (or JSON variant) is empty, Telegram DMs are blocked.
- Missing required env vars referenced in the template can block startup or leave the affected feature unavailable.
- To change the model or allowlist later, update the env vars and redeploy.

## Setup flow

1. Visit `https://<your-railway-domain>/setup` and enter your `SETUP_PASSWORD`.
2. Choose a model/auth provider and paste your key.
3. (Optional) Add Telegram/Discord/Slack tokens.
4. Click **Run setup**.

If Telegram DMs are set to pairing, the setup wizard can approve the pairing code.

## Getting chat tokens

### Telegram bot token

1. Message `@BotFather` in Telegram
2. Run `/newbot`
3. Copy the token (looks like `123456789:AA...`)
4. Paste it into `/setup`

### Discord bot token

1. Go to [https://discord.com/developers/applications](https://discord.com/developers/applications)
2. **New Application** → choose a name
3. **Bot** → **Add Bot**
4. **Enable MESSAGE CONTENT INTENT** under Bot → Privileged Gateway Intents (required or the bot will crash on startup)
5. Copy the **Bot Token** and paste into `/setup`
6. Invite the bot to your server (OAuth2 URL Generator; scopes: `bot`, `applications.commands`)

## Backups & migration

Download a backup at:

- `https://<your-railway-domain>/setup/export`

This exports your OpenClaw state + workspace so you can migrate to another host without losing config or memory.
